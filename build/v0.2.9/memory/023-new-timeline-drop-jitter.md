# New Timeline Drop Jitter

## Change

- Restored the drop fallback dispatch in `OsFileManager.tsx` and `FileManager.tsx` so the custom timeline drop can still commit if the external drag bridge was cleared before the native `drop` event. This fixes the inability to drop compositions on any timeline.
- Stabilized direct timeline external composition drag targets. The pointer-drag resolver no longer returns a synthetic empty row key or falls back to the first unlocked composition row when the pointer is outside a composition lane, which prevented the preview from alternating between invalid and fallback targets while hovering gaps/default timeline space.
- Removed duplicate `compositionDragPreviewEvent` listeners from both file-manager implementations. Each preview active/inactive event now produces one file-manager state update instead of two redundant updates during marker hover.
- Kept the earlier fix to align editor derived timeline state with the active `TimelineDocument.timelineLayers` instead of falling back to legacy `project.editorState.timelineLayers`. This ensures new timelines (which only have local/default layer state) use the same row model for preview, selection, blocking, and drop calculations.
- Deeper follow-up: coalesced Direct timeline external effect/composition pointer drag `move` handling with `requestAnimationFrame`, deduped equivalent preview payloads, and suppressed repeated drag-active / preview-active events. Drops flush any pending move first so snapping, blocking, and target selection still use the latest hover position before committing.
- Targeted verification fix: `DirectTimelinePanel` now recomputes the external pointer-drag preview from the actual drop event coordinates before committing. Composition/effect pointer drops use the same preview helpers as hover, preserving snap/clamp/blocking calculations without depending on stale last-hover state.
- Targeted cleanup fix: `DirectTimelinePanel` unmount cleanup clears pending pointer-drag refs, active composition drag state, and emits inactive preview events for any active composition/effect drag preview flags. `FileManager` now mirrors `OsFileManager` by cancelling an active external composition drag on unmount.
- Restored custom pointer drop registration after strict target recompute by tracking the last valid external pointer-drop row in `DirectTimelinePanel`. Final `drop` still recomputes from the release coordinates first, but if that exact recompute produces no row while the pointer is still over the timeline shell, the drop can commit through the last real row target instead of disappearing. The fallback is ref-only, cleared on cancel/drop/invalid resolution, and does not reintroduce first-row/default-row hover fallback.
- Fixed a stale native-drag coordinate path in `FileManager.tsx` and `OsFileManager.tsx`. The external timeline drag bridge now records the native drag-start client/screen coordinate, synthesizes current client coordinates from screen deltas when Electron repeats the initial `clientX/clientY`, and preserves the last bridge coordinate for fallback drop dispatch after premature cleanup. Move/drop dispatch still flows through rAF-coalesced refs and does not write project state during hover.
- Follow-up fix: removed the extra `drag`, `pointermove`, and `mousemove` bridge listeners from `FileManager.tsx` and `OsFileManager.tsx`. During native HTML drag, those events can report the original drag-start coordinate and race with `dragover`, causing the timeline preview to snap back to the first coordinate. The bridge now has a single coordinate stream for native composition drags: corrected `dragover` for hover and corrected `drop` for commit.
- Timeline-side fix: restored the prior no-remount rule for coordinate-only external preview changes in `DirectTimelinePanel`. `initialClientX` and `initialStart` are not semantic preview identity, so including them in `shouldRemount` made the composition preview remount during hover instead of moving imperatively, which matches the repeated marker jitter described in this task.
- Reverted the experimental project File Manager external composition drag bridge changes and restored timeline viewport drag handlers to the content element. The drag/drop path had worked before the handler experiments; the actual root cause was missing timeline rows, so handler behavior should stay on the known-good path while default layer creation/load repair owns the fix.
- Reverted the remaining drag/preview experiments: restored the File Manager and OS File Manager preview-active listeners, restored the composition preview block's initial inline style, and restored transition row category detection. The fix should not depend on handler/preview rewrites now that timelines are guaranteed to have rows.
- Restored the remaining file-manager behavior from before the handler experiments, including the duplicate preview listener structure and OS `file-manager/` path stripping. The remaining source fix for this issue should be default timeline layer creation/load repair, not drag bridge changes.
- Fixed native drop acceptance by setting `application/x-clipper-composition` during composition row drag-start in both File Manager implementations. Direct timeline drag-over uses that MIME type to call `preventDefault()`, and browsers do not fire `drop` unless the final target accepted drag-over.
- Fixed the OS File Manager drag-start payload to use `effectiveDirectory` in row scope instead of the unavailable outer `projectDirectory`. The ReferenceError prevented `setDragImage()` from running, which brought back the native default drag ghost and also prevented the composition MIME payload from being set.
- Fixed a native drag operation mismatch in `NativeTree`: composition rows set the `application/x-clipper-composition` payload and timeline accepts with `dropEffect = "copy"`, but the shared tree was forcing `effectAllowed = "move"` afterwards. Composition drags now use `copyMove`, while ordinary tree moves stay `move`, so the browser can legally emit timeline copy drops.

## Architecture Note

- Timeline row layout is timeline-local state. Shared derived editor calculations should receive the active timeline layer state from `App.tsx` rather than independently reading legacy editor state.
- File manager composition drags should dispatch the custom drop event even if the native `dragleave` triggered `cleanupExternalCompositionDrag` prematurely, since the browser's native `drop` can still fire.
- External drag target resolution in `DirectTimelinePanel` should be strict: preview/drop must use the actual row under the pointer and clear preview when no matching row exists. Do not fall back to an arbitrary unlocked row during pointer movement; that creates visible target thrash and can commit to a lane the cursor never touched.
- File-manager drag preview feedback should subscribe to `compositionDragPreviewEvent` once per component. Duplicate listeners are easy to miss because they are functionally equivalent, but they double React state traffic during high-frequency drag hover.
- External timeline drag hover is a hot path owned by `DirectTimelinePanel`. Native File Manager / OS File Manager drags may dispatch move events faster than React should render, so the timeline should keep transient hover payloads in refs, process only the latest move per frame, and only emit preview visibility changes on active/inactive transitions.
- The actual remaining jitter source was event/state churn during hover, not persisted project mutation: every custom move could recompute targets, call React state setters, clear/update snap guides, and dispatch preview-active events even when the snapped preview was unchanged. The fix keeps preview DOM movement imperative and prevents identical hover frames from remounting or re-notifying the drag ghost.
- Drop commits must be computed from the final drop coordinates, not from the last coalesced hover frame. It is acceptable to flush a pending hover before drop for visual continuity, but the drop phase must call the current preview calculation once more before reading preview state for commit.
- Preview-active events are paired lifecycle state. Any path that cancels frames or clears pointer-drag state (cancel, drop, unmount) should also emit inactive events through the deduped preview-active helper so external drag ghosts and lane previews do not remain hidden/active.
- Final drop resolution now has a narrow safety net for native/custom drag lifecycle edge cases: only a previously resolved real timeline row can be reused, only during the `drop` phase, and only when the pointer is still over the timeline but exact row resolution returns nothing. Movement remains strict and continues to avoid synthetic row/default-row targets, preserving the jitter fix.
- File-manager native drag events in Electron can report the drag-start client coordinate while the OS-level screen coordinate changes. External timeline drag bridges should prefer current client coordinates when valid, but when native client coordinates equal the recorded drag start and screen coordinates have moved, derive the client coordinate from the drag-start client plus screen delta. This keeps preview/drop coordinate propagation current without introducing timeline row fallbacks.
- Native composition drag bridges should not mix `dragover` with `drag`/`pointermove`/`mousemove` coordinate streams. Browser/Electron native DnD may freeze or replay pointer-style client coordinates while dragover/drop carry the useful native drag position, so mixed streams can overwrite the latest hover with the original coordinate every frame.
- External timeline preview identity must exclude coordinate-only fields such as `initialClientX` and `initialStart`. Those values can change as a derived base is recreated during hover, but the preview should stay mounted and update its transform/width through `applyEffectDragPreviewElement()`.
- Do not compensate for missing timeline rows by changing file-manager or timeline native drag handlers. If rows are missing, repair timeline documents at creation/load time so existing drag/drop handlers have stable row targets.
