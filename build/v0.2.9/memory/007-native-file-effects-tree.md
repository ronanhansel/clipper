# Native File Manager And Effects Tree

## Change
- Replaced Arborist rendering in the app File Manager/assets tree and OS-backed File Manager with `src/components/tree/NativeTree.tsx`.
- Updated the Effects pane to use the same native tree component with `movable={false}`.
- Kept Compose page Arborist usage intact in `src/components/compose/ComposeLayersPanel.tsx`; `react-arborist` remains a dependency.
- Removed duplicated File Manager drop handling that combined pointer-derived native drop targets with Arborist DnD fallback state.
- Added effect grouping parsing support for both `group: "A/B"` and `groups: ["A", "B"]` in `src/core/effects/manifest.ts`.

## Architecture Notes
- `NativeTree` owns shared tree state for expansion, selection, focus, editing, optional native drag/move, and drag preview plumbing.
- File Manager uses `movable` to preserve drag/move/reorder semantics and supplies domain-specific drop target validation.
- Effects uses the same tree primitive with moves disabled, so grouping, expansion, and row rendering match File Manager without carrying duplicate Arborist/native event paths.
- Empty folders/groups are supported through the `isInternal` accessor rather than inferring folder-ness only from non-empty `children`.

## Verification Fixes
- Fixed native File Manager move insertion by adjusting the drop index from dragged siblings that originally appeared before the target sibling index, not from drag selection order. The May 02 follow-up replaced the remaining `dragIds.slice(0, index)` calculation with original sibling-order based adjustment and covered it with a focused helper test.
- Removed the stale `overscanCount` prop from `NativeTree` and its File Manager/OS File Manager call sites because the native tree is not virtualized.
- Confirmed `ArboristClickRow` had no imports after the native File Manager/Effects migration and removed it; Compose Arborist remains intact in `src/components/compose/ComposeLayersPanel.tsx`.
- Added `src/core/effects/manifest.test.ts` coverage for explicit `groups:` parsing and nested `group:` fallback behavior.
- Removed stale Arborist internal-root sentinel handling from `OsFileManager`; native root moves are represented by `null`.
- Removed unused legacy File Manager order helpers (`applyFileTreeOrder`, `moveFileTreeOrder`, and their private support helpers) after confirming they had no callers.
- May 02 correction unified File Manager, OS File Manager, composition/timeline, and effect drag ghosts around the shared Clipper ghost style. The old `.composition`/`.timeline` native preview branches were removed, preview labels now omit those semantic suffixes through the drag-preview display-name helper, and composition previews use the same offset as files/effects.
- May 02 follow-up removed the remaining inside/outside visual handoff behavior from both File Manager implementations. Composition drags keep NativeTree as the owner of the native drag, start the external composition pointer bridge only after leaving the owning File Manager panel, and use the bridge only for timeline/editor preview/drop/cancel dispatch.
- Timeline and no-target drops from File Manager/OS File Manager composition drags now always dispatch the shared composition pointer `drop` event and synchronously call `NativeTree.endDrag()` during bridge cleanup. This mirrors effect marker lifecycle behavior: no-op drops clear the custom ghost immediately, while valid timeline lane previews own visual feedback.
- File Manager and OS File Manager drag previews listen to the shared `compositionDragPreviewEvent` and hide their NativeTree ghost while a valid composition marker preview is active, then show it again as soon as the lane preview clears. This reuses the same preview-active signal used by effect pointer ghosts rather than boundary-based suppression state.
- Removed the old `internalDragOutsideTree`, `suppressDropState`, boundary drag-leave cursor hiding, and timeline hit-test drop branching from File Manager/OS File Manager. Internal NativeTree move/drop semantics remain local to NativeTree; external composition bridge suppression is limited to drag events outside the owning File Manager panel.
- `NativeTree` exposes `endDrag()` for callers that need to cancel both the native drag preview and drop cursor together; File Manager composition bridge cleanup now uses it only on external drop/cancel finalization, not for inside/outside visual handoff.
- `NativeTree` now exposes contiguous drop-block start/end flags in addition to `willReceiveDropWithin`; File Manager rows use them to render one continuous expanded-folder highlight over the folder row and all visible descendants instead of disconnected per-row highlighting. The expanded-folder block highlight intentionally has square edges/no rounded border radius.
- The File Manager root drop highlight no longer applies rounded borders; it uses only square-edged background/shadow feedback so folder/root targets visually match row block highlights.
- May 02 follow-up added empty-space root interactions for both File Manager implementations. The project File Manager now opens its root create context menu from non-row empty areas and treats the area below visible rows as a root drop target (`parentId: null`) so compositions, timelines, composition folders, and root-reorderable assets can be moved out of folders while preserving existing helper validation. OS File Manager now allows NativeTree root drops by mapping `parentId: null` to the effective directory for filesystem moves, opens the existing root creation menu from empty non-row areas, and uses the same square-edged root highlight; OS creation still creates compositions under the `compositions` subfolder and timelines under the `timelines` subfolder when invoked at the effective root, matching its existing behavior.
- May 02 drag lifecycle correction moved composition pointer drag state/event dispatch into `dispatchClipperPointerDrag()` in `src/lib/pointerDrag.ts`, the same shared path used by effect pointer drags. File Manager and OS File Manager no longer set active composition drag state directly; they only construct domain payloads and dispatch through the shared handler.
- `NativeTree` now clears both `dropTarget` and `dragState` immediately when a drop has no valid target. This matches the effect pointer drag cleanup behavior where no-op drops synchronously discard the ghost/preview instead of waiting for a later native `dragend`/window cleanup.
- Removed root drop-highlight transition classes from both File Manager implementations so moving items out of folders does not animate differently from row/folder drop previews.
- `NativeTree` now keeps the active drag alive during transient invalid `dragover` positions and only clears the ghost on an actual invalid `drop`. The project File Manager drop resolver also falls back to the nearest valid sibling/root index when the raw row-edge target is invalid, which keeps adjacent rows tightly coupled and prevents preview stutter in tiny in-between zones without relaxing the existing domain drop constraints.
- Centralized immediate native tree drag finalization in `NativeTree.finishDrag()`, using `flushSync` for drop, dragend, invalid-drop, and imperative `endDrag()` cleanup. This makes folders, timelines, files, and compositions discard their React-rendered ghost immediately on no-op drops instead of only composition rows benefiting from the external composition bridge cleanup.
- Follow-up fix: the global NativeTree `drop` cleanup must not run in capture phase because it clears `dragState` before the tree's own `onDrop` can resolve and commit `onMove`. The listener now runs in bubble phase, so internal file moves commit first while outside/no-op drops still clear the shared ghost immediately.
- Added a document-capture outside-drop cleanup in `NativeTree` that only fires when the drop target is outside the tree container. This keeps internal moves working while ensuring all native rows (folders, timelines, files, and compositions) discard their ghost immediately when dropped elsewhere in the app, even if another capture handler stops propagation.
- Suppressed native browser "snap-back" animations by calling `preventDefault()` on a global `dragover` listener in `NativeTree`. This ensures that drops on invalid targets result in an immediate ghost disappearance rather than a delayed OS-level fly-back animation, matching the instantaneous behavior of effect markers.
- Project File Manager and OS File Manager composition rows now tint both the composition icon and display text green (`#38d996`). The shared drag ghost for compositions also inherits this green theme for consistent visual identification.
- Fixed a final discrepancy where normal files were lingering longer than compositions by unifying the `endDrag()` call path during any external drop or window exit.
