# Zip Container Project State

- Goal: make `.clipper` the primary project save format. A `.clipper` file is a zip container with `project.json`, `timelines/*.json`, and `compositions/*.ts` entries.
- Project state is split conceptually into project/file management, timelines, and reusable compositions. The runtime still exposes legacy scene/composition aliases during migration so the editor can move incrementally without losing behavior.
- Undo/redo remains memory-only. Save writes active state to disk and does not clear history. Deleted compositions are recoverable through the in-memory undo stack while the project remains open, but deleted composition files are not persisted into the saved `.clipper` zip.
- Persistence rewrites the zip from active state only. This physically purges deleted compositions from the saved container on save while allowing `delete -> save -> undo -> save` in the same session.
- Legacy `project.json` loading is migration-only: it normalizes old scenes/library/sources into timeline and composition fields before saving as `.clipper`.
- Current demo container: `clipper/projects/prj_white_serif_demo.clipper`. `clipper/app-state.json` points startup at this file. The old `clipper/projects/prj_white_serif_demo/project.json` is only legacy source material.
- Loader detail: composition IDs must be extracted from `export const composition = new Composition({ id: ... })`, not from the first `id` property in the source. Earlier parsing grabbed child object IDs such as `paper-wash`, causing timeline clips to reference missing compositions.
- Crash hardening: `useEditorDerivedState` now falls back to an empty timeline/composition if a container has no resolvable clips. This prevents `part.duration` crashes while keeping malformed containers visible enough to recover or inspect.
- File Manager UI: timelines are rendered as ordinary root-level project file rows in the same tree as composition files, not as a separate section/tab. Timeline rows use file styling, support select/rename/delete from the same context-menu pattern, and remain conceptually files inside the `.clipper` container.
- File Manager icon rule: timeline rows use the timeline/Gantt icon, while composition rows use the clapperboard icon so the two project-owned file types remain visually distinct.
- File Manager interaction rule: rows should not keep persistent selection highlights after clicking elsewhere. Imported asset rows no longer persist local selected styling, outside pointer clicks blur active controls, and timeline row highlighting is limited to drag/drop previews.
- Timeline rows now support drag reordering in the File Manager. Reordering updates both `project.timelines` and the legacy-compatible `project.scenes` order so the active editor and saved container stay aligned.
- Maintainability requirement from user feedback: do not grow `FileManager` with long nested prop chains for timeline/composition/folder actions. Shared file-management state/actions should move behind a scoped Zustand store/provider or narrow controller hook, with components subscribing through selectors instead of receiving many threaded callbacks.
- Current refactor target: the existing `FileManager` composition/timeline tree has become too prop-heavy while adding folder organization. Before adding more project-file operations, extract the File Manager command surface and transient rename/drag/drop state into a scoped Zustand store or controller hook, then let rows/folders subscribe narrowly.
- File Manager refactor: the project-owned composition/timeline tree now uses a scoped Zustand provider in `src/components/FileManager.tsx`. The provider owns transient rename/drag/drop/collapse state and exposes semantic actions such as `commitRename`, `moveDropToFolder`, and `toggleFolder`; row/folder components subscribe with narrow selectors instead of receiving the previous recursive callback chain.
- Timeline folder move fix: `moveTimeline()` updates `TimelineDocument.filePath`, and `normalizeProject()` must preserve existing timeline metadata when legacy runtime `scenes` are present. Earlier normalization regenerated timelines from scenes with default `timelines/{id}.timeline.json` paths, so drops appeared to do nothing.
- File Manager tree DnD replacement: project-owned files now use `react-arborist` instead of custom native HTML5 row/folder drag handlers. Arborist provides deterministic `onMove({ dragIds, parentId, index })` semantics and owns drag cursor/drop highlight cleanup. Same-parent timeline drops are treated as reorder-only; different-parent drops move the timeline/composition into the destination folder.
- Arborist drag polish: use a compact custom `renderDragPreview` for project files instead of the default screenshot preview, which stretched full-width rows across the screen. Project-file rows also avoid transition classes during drag to reduce drag-time repaint work.
