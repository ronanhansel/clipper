# App Feature State Extraction

## Goal

Move feature orchestration out of `src/App.tsx` into named feature folders. The first slice focuses on timeline state/provider boundaries and file-manager prop construction while preserving existing project mutation semantics.

## Architecture Notes

- `src/app/features/timeline` owns the Timeline panel provider boundary. It bridges the current App-level timeline controller into a scoped Zustand store so Timeline UI can subscribe through a feature-local provider instead of receiving a long prop chain directly from `App.tsx`.
- `src/app/features/file-manager` owns the File Manager prop assembly, implicit file-operation wrapping, and project-side asset/composition/timeline file actions. `App.tsx` now passes narrow project/editor dependencies into the file-manager hooks instead of defining thin wrapper callbacks inline.
- This slice intentionally avoids changing timeline editing behavior. It introduces the folders and state boundary first, then later timeline mutation commands can migrate behind the provider one group at a time.
- Project manifest boot path helpers now live in `src/app/project/activeProjectManifest.ts`, and composition source snapshot/sync helpers live in `src/app/project/projectSources.ts` so source persistence no longer sits in the root UI file.
- File manager project transforms are split by domain: `assetProjectMutations.ts`, `compositionLibraryMutations.ts`, `compositionFolderMutations.ts`, and `timelineLibraryMutations.ts`. `useFileManagerProjectActions.ts` owns the side-effect wrappers for source-ref updates, selection/editor-state updates, toasts, and clipboard/reveal operations; `useFileManagerController.ts` still applies `implicitFileOperation` to mutating File Manager actions before returning `FileManagerWorkspaceProps`.
- Timeline marker rewrite mechanics live in `src/app/features/timeline/timelineMutationHelpers.ts`. App timeline commands now call shared helper functions instead of carrying low-level overwrite/mend conversion code inline.
- Editor panel resize rAF preview/commit behavior now lives in `src/app/features/editor-layout/useEditorPanelResize.ts`, preserving the existing imperative CSS preview and single commit on pointer release.
- Left sidebar presentation now lives in `src/app/shell/LeftSidebar.tsx`, keeping compose layers, File Manager, and Tools Panel rendering out of `App.tsx` while App still supplies controller callbacks.
- Project document lifecycle now lives in `src/app/project/useProjectDocumentController.ts`, centralizing project refs, source refs, history, undo/redo, save, implicit file-operation save scheduling, open-project handling, and composition-source updates behind a single controller API.
- Active project boot/open fallback logic now lives in `src/app/project/useActiveProjectBoot.ts`; `App` only renders boot/loading/error branches and hands the loaded document into providers.
- Debounced editor-state persistence now lives in `src/app/project/useEditorStatePersistence.ts`, keeping background editor-state saves out of `App.tsx` while preserving the existing 250ms debounce.
- Composition folder ordering, rename/move/delete, and File Manager tree snapshot project transforms now live in `src/app/features/file-manager/compositionFolderMutations.ts`, keeping path/source remapping pure and reusable.
- Dialog/overlay rendering now lives in `src/app/shell/AppDialogs.tsx`; playback-bar rendering now lives in `src/app/shell/PlaybackBar.tsx`.
- Timeline layer factories and clip conversion now live in `src/app/features/timeline/timelineLayerHelpers.ts` as pure helpers reused by App's remaining timeline commands.
- Header and presentation-control rendering now use `src/app/shell/AppHeader.tsx` and `src/app/shell/PresentationControls.tsx`; `App.tsx` only supplies state and callbacks for project rename, save/open/export/settings, and presentation scrubbing/playback.
- The center preview shell now lives in `src/app/shell/PreviewColumn.tsx`. It is intentionally presentational: frame/code props, refs, mode switching, scroll save callback, and playback bar children are supplied by `App.tsx` so pointer, rAF, and playback commit semantics remain unchanged.
- The right inspector chrome now lives in `src/app/shell/RightInspectorPanel.tsx`, preserving `data-inspector-panel` for outside-click behavior. The large inspector body conditional remains in `App.tsx` because it closes over many selected-node/object handlers and should be split by inspector domain in a later slice.
- File Manager prop assembly and implicit-file-operation wrapping live in `src/app/features/file-manager/useFileManagerController.ts`. The individual project/source mutation callbacks and File Manager side effects now live in `src/app/features/file-manager/useFileManagerProjectActions.ts`, preserving source refs, selection clearing, editor-state timeline selection, toasts, clipboard copy, and Finder reveal behavior.
- Low-risk timeline project/editor commands now live in `src/app/features/timeline/useTimelineProjectActions.ts`: scene part updates, scene motion/adjustment marker updates, current part updates, timeline-part composition updates, viewport updates, and timeline layer state updates. Layer deletion commands remain in App for now because they also clear selection and picker state.
- Timeline selection commands now live in `src/app/features/timeline/useTimelineSelectionCommands.ts`. The hook receives only App-owned setters, refs, and current values, preserving frame-pick cancellation, tracker-pick clearing, object selection clearing, playback stopping, compose-mode switching, and scene-time scrubbing without adding broad Zustand subscriptions.
- Timeline layer row commands now live in `src/app/features/timeline/useTimelineLayerCommands.ts`. The hook reuses timeline layer factories/helpers and `useTimelineProjectActions`'s `updateTimelineLayers`, while preserving layer deletion history semantics, marker filtering, and selection/picker clearing when deleted layers contained selected content.
- Composition timeline commands now live in `src/app/features/timeline/useCompositionTimelineCommands.ts`. The hook owns reorder, move, update, delete, multi-delete, and add-from-library behavior while preserving layer IDs, marker rebase behavior, post-delete/add selection, and project-history semantics through `updateSceneParts`.
- Adjustment effect commands now live in `src/app/features/timeline/useAdjustmentLayerCommands.ts`. The hook owns update, move, add-at-current-time, add-at-target-layer, delete, and point-pick start/toggle behavior while App still owns frame pointer commit orchestration. Pure adjustment overwrite and control-to-frame-point helpers live in `src/app/features/timeline/timelineMutationHelpers.ts` so paste, add, move, inspector updates, and frame pick previews share the same split/placement semantics.
- Center preview pane composition now lives in `src/app/shell/CenterPreviewPane.tsx`. It owns only the pane-local hover state used to reveal the playback border scrubber and composes `PreviewColumn` with `PlaybackBar`; all playback, scroll persistence, frame interaction, and rAF commit callbacks still come from `App.tsx`.
- Editor resize chrome now lives in `src/app/shell/EditorWorkspace.tsx` with `TimelineResizeHandle`. The shell renders the pane resize separators, but continues delegating pointer-down events to `useEditorPanelResize` so the existing imperative preview and commit-on-release behavior remains unchanged.
- Motion marker commands now live in `src/app/features/timeline/useMotionMarkerCommands.ts`. The hook owns zoom/translation/rotation add, update, move, resize, delete, selected snap toggles, middle snap/transition/ease commands, focus/position updates, scale-preview rAF scheduling, and scene-level `addMotionEffect` while App keeps frame pointer interactions in place.
- Timeline-level motion marker paths continue to write `TimelineDocument.zoomMarkers` / `translationMarkers` via `updateSceneMotionMarkers` and preserve `TIMELINE_MOTION_PART_ID`, mended IDs, layer retagging/history, overwrite trimming, and post-command marker selection.
- Presentation orchestration now lives in `src/app/features/presentation/usePresentationController.ts`. The hook owns presentation mode state, controls visibility timeout, presentation display-time rAF sync, scale measurement, fullscreen/window fullscreen listeners, theater/frame enter/exit, and presentation scrub display updates while `App.tsx` still supplies playback commands and scene-time scrubbing.
- The settings shortcut listener now lives in `src/app/features/shortcuts/useSettingsShortcut.ts`, preserving both `Cmd/Ctrl+,` and the Electron-host settings shortcut bridge without keeping that global key listener inline in `App.tsx`.
- Timeline clipboard, cut/copy/paste/delete, silent paste, and timeline blank/node context-menu orchestration now live in `src/app/features/timeline/useTimelineClipboardCommands.ts`. The hook owns the clipboard ref and receives existing adjustment/composition/motion mutation and selection commands from `App.tsx`, preserving toast text, menu items/coordinates, paste IDs, target-start semantics, and post-paste selection while keeping frame/playback controllers in App.
- Shell/editor-layout helpers now own the remaining low-risk App shell commands: `useEditorModeCommands` updates editor/timeline mode refs plus persisted editor state, `useCodeViewportState` persists code scroll positions with no-op suppression, `useProjectTitleRename` owns title context-menu/rename/cancel behavior, `useFramePreviewZoomCommands` owns zoom scale clamping and outside-click zoom-bar dismissal, and `usePreviewScrollPersistence` owns rAF-throttled center preview scroll persistence.
- Playback and file-manager controller extractions were present during this slice and were reconciled rather than reverted. `App.tsx` now delegates playback commands/effects to `usePlaybackController` and file-manager project actions to `useFileManagerProjectActions`, while this slice keeps the requested shell/editor-mode extractions separate and narrow.
- Playback orchestration now lives in `src/app/features/playback/usePlaybackController.ts`. The hook owns playback DOM syncing, visual-adjustment overlay DOM syncing during timeline scrubs, playback clock/playhead editor-state commits, playback rAF advancement, display-time scrubbing, timeline/presentation/number-input scrub pause-resume, and play/step/jump commands while `App.tsx` keeps the existing refs and passes narrow state/setter dependencies into the hook.
- Global editor keyboard handling now lives in `src/app/features/shortcuts/useGlobalEditorShortcuts.ts`. The hook owns save, mode switching, Electron mode shortcuts, presentation shortcuts, undo/redo, timeline clipboard, playback stepping/toggling, snap/fast-select toggles, and deletion routing while preserving the same target guards and App-owned command dependencies; pure code/text target predicates moved with the hook and `App.tsx` reuses the code-editor guard for outside-frame pointer handling.

## Follow-Ups

- Frame interaction controllers remain intentionally in App for now.
- Continue narrowing the dependency list passed from `App.tsx` into `useFileManagerProjectActions` if project document/save APIs are further consolidated.
- Extract project history/save orchestration into a `useProjectDocumentController` hook so feature controllers can receive a narrow `updateProject/updateEditorState/implicitFileOperation` API instead of closing over root refs.
- Split the inspector body conditional into focused inspector controller/render modules after the selected object/marker/layer command handlers are grouped.
- Frame interaction controllers remain high-risk because they depend on rAF DOM updates, transient refs, and commit-on-release semantics; extract only with targeted interaction tests or careful manual verification. Playback is now separated behind a ref-driven controller hook, but global timeline/object keyboard shortcuts remain in `App.tsx`.
